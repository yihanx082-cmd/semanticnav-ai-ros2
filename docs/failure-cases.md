# SemanticNav AI 失败案例

本文记录当前软件原型在真实视频上的失败现象、原因、现有处理和后续改进。统计基于三段视频各30帧，不等价于带人工逐框标注的mAP评测。

## 1. 预训练类别覆盖不足

**现象：** 用户视频中存在拖鞋，但`yolo26n.pt`使用的COCO类别没有`shoe`和`cable`，因此系统无法可靠识别“拖鞋”和“电线”。

**原因：** 类别不存在不是降低置信度可以解决的问题。模型只能在训练类别中选择，甚至可能把未知物体误判成相似类别。

**当前处理：** README和页面明确说明类别边界；任务解析器可以生成`shoe`或`cable`避让约束，但感知层没有对应检测时不会伪造障碍物。

**未来改进：** 收集室内地面障碍数据，增加`shoe`、`cable`等自定义类别；分别报告自定义测试集精度和失败样本。

## 2. 遮挡和间歇检测造成轨迹碎片

**现象：** 人物场景中`person`连续30帧保持ID 1，但右侧瓶子先后得到ID 2和ID 12，记为一次轨迹碎片化。

**原因：** 小目标占用像素少，人物移动和前景变化会使检测置信度短暂下降。ByteTrack可以连接部分低分框，但目标消失过久后仍会创建新轨迹。

**当前处理：** 输出轨迹ID而不是声称具有永久物体身份；使用`evaluate_scene.py`同时报告每类检测次数和全部轨迹ID。

**未来改进：** 在固定数据上调节ByteTrack缓冲长度和匹配阈值；若岗位需求强调跨遮挡身份，再评估带ReID的跟踪器。

## 3. 厨房柜体误识别为冰箱

**现象：** 猫场景中`cat`为ID 1并保持30/30帧，`oven`出现23帧，但绿色柜体在3帧中被识别为`refrigerator`。

**原因：** 厨房柜门的矩形结构、把手和周围电器语境与冰箱外观相似；低分辨率缩放进一步减少纹理信息。

**当前处理：** 三场景表将这3次记录为已确认假阳性；页面保留置信度，使用者可以检查低置信度目标。

**未来改进：** 增加时间一致性过滤，要求非动态障碍连续出现若干帧后再进入高代价区域；对目标类别使用不同阈值。

## 4. 单目相对深度不等于真实距离

**现象：** Depth Anything V2可以把目标分为近、中、远，但不同视频、焦距和场景尺度下的数值不能直接比较，更不能解释为米。

**原因：** 当前没有相机内参、真实深度标定和绝对尺度约束。

**当前处理：** JSON只输出`relative_depth`和`depth_level`；页面、地图和文档固定标注“非米制”。

**未来改进：** 使用公开RGB-D数据读取深度图和相机内参，通过中心区域中位数和反投影输出`X/Y/Z`，并用合成点验证误差。

## 5. CPU深度推理和高分辨率写出较慢

**现象：** 480检测基准达到4.076 FPS；开启每5帧一次深度后下降到0.532 FPS。两段4K素材即使YOLO输入仍为480，端到端FPS也只有0.786和1.368。

**原因：** 深度模型运行在CPU上；此外，检测前缩放并不会降低标注视频以原始4K尺寸绘制和编码的成本。

**当前处理：** 默认关闭深度、默认480输入、深度间隔设为5，Demo只处理短片段；页面不宣称实时。

**未来改进：** 增加可选输出分辨率，演示时将4K视频缩放到720p；之后再比较ONNX或GPU，而不是在没有数据时宣称加速。

## 6. 评测边界

当前场景表用于工程诊断，而非正式模型精度报告：

- 没有逐帧、逐框人工真值；
- `false_positives`只统计抽查画面中能够确认的错误；
- 多个轨迹ID不一定代表ID切换，也可能是多个真实实例；
- `path_success=True`只表示30×30示意栅格中A*找到路径，不表示真实机器人导航成功。
