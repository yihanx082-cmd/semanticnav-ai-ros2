# SemanticNav AI Task 3～10 实验报告

## 1. 实验目的

验证快速版软件闭环是否能够在无CUDA、无机器人和无RGB-D相机的条件下完成：

```text
室内MP4
  → YOLO检测
  → ByteTrack持续ID
  → 单目相对深度
  → 局部示意语义地图（非米制）
  → 障碍膨胀与A*
  → 中英文规则任务解析
  → 标注视频、JSON、CSV和PNG导出
```

本报告只陈述实际实现和实际测量结果，不将相对深度解释为米制距离，
不将示意路径描述为真实机器人底盘控制。

## 6. 检测与跟踪结果

### 6.1 输入尺寸

从640降到480后：

- 平均FPS从2.766提高到4.221，提升约52.6%；
- YOLO平均推理从259.292 ms下降到148.218 ms，下降约42.8%；
- `chair`在两组实验中均出现30/30帧；
- `couch`从30/30帧变为28/30帧，出现少量漏检；
- `chair`和`couch`在各自实验中均只使用一个轨迹ID。

因此，480是当前CPU环境下更适合交互演示的默认输入尺寸；640适合离线生成
质量稍高的结果，但当前实时性不足。

### 6.2 置信度阈值

将阈值从0.25提高到0.60后：

- 平均目标数从每帧3.5个下降到2.0个；
- `chair`由30/30帧下降到29/30帧；
- `couch`由30/30帧下降到2/30帧；
- 一条高置信度`vase`误检仍持续出现29/30帧。

结论：提高阈值能够过滤部分低置信度结果，但无法消除高置信度类别误判，
同时会显著增加沙发漏检。当前样例推荐保持`confidence=0.25`。

### 6.3 失败案例

画面中的室内摆件和部分家具结构被识别为`vase`。这不是ByteTrack错误，而是
预训练检测模型的类别判别误差。ByteTrack只负责关联检测框，不会修正YOLO类别。

本实验不使用主观方式把误检改名，也不在没有标注真值的情况下报告mAP。
后续若必须识别拖鞋、电线等类别，需要单独采集、标注和训练自定义检测数据。

## 7. 相对深度结果

E4共处理6帧，深度间隔为3，因此实际运行2次深度模型，其余帧复用最近深度图。

| 帧号 | 总处理延迟/ms | YOLO推理/ms | 说明 |
|---:|---:|---:|---|
| 270 | 6709.2 | 195.5 | 运行深度模型 |
| 271 | 190.4 | 159.1 | 复用深度图 |
| 272 | 181.4 | 144.7 | 复用深度图 |
| 273 | 5832.1 | 146.7 | 运行深度模型 |
| 274 | 121.1 | 95.2 | 复用深度图 |
| 275 | 343.7 | 313.1 | 复用深度图 |

首帧代表性结果：

| 类别 | 相对深度 | 等级 |
|---|---:|---|
| chair | 0.128 | far |
| couch | 0.123 | far |
| vase | 0.448 | mid |

结果JSON中不存在`distance_m`字段。当前数值只表示同一帧归一化后的相对远近，
不可解释为米、厘米或真实三维坐标。

当前CPU上，深度模型是主要性能瓶颈：相对E2，开启深度后平均FPS下降约90.5%。
可采用的优化顺序为：

1. 深度间隔由3提高到5；
2. 演示前预计算深度；
3. 页面处理时关闭逐帧预览；
4. 最后才考虑短时云GPU。

## 8. 地图与规划结果

- 地图固定为30×30栅格；
- 地图名称记录为“局部示意地图（非米制）”；
- 机器人固定在底部中央；
- 未知深度目标不会生成虚假障碍；
- 普通障碍、应避让目标和阻塞区域使用不同代价；
- 障碍膨胀半径为2格；
- A*使用八邻域并禁止斜穿障碍角。

无深度实验中，目标深度均为`unknown`，因此地图不生成假障碍，路径为直线路径，
长度29格。E4启用相对深度后，目标进入示意栅格，A*成功规划，路径长度约
21.657格。

上述路径只表示局部示意地图中的软件规划结果，不是SLAM地图、Nav2路径或真实
机器人运动轨迹。

## 10. 推荐演示配置

```yaml
model:
  name: yolo26n.pt
  confidence: 0.25
  image_size: 480

tracker:
  name: bytetrack.yaml

depth:
  enabled: true
  frame_interval: 5
```

如果演示重点是流畅检测与跟踪，建议关闭深度。如果重点是展示完整软件闭环，
建议只处理短片段或预计算深度。

## 11. 结论

Task 3～10已经形成可测试、可复现、可导出的软件闭环。YOLO和ByteTrack在当前
片段上能够持续检测并跟踪椅子和沙发；480输入在CPU上取得更合适的速度；规则
解析、非米制地图和A*均通过自动测试。主要限制是单目深度CPU延迟高、COCO类别
不包含拖鞋和电线，以及当前路径未接入真实底盘。

因此，当前版本可准确描述为：

> 基于YOLO、ByteTrack、单目相对深度、局部示意语义地图与A*的室内机器人视觉
> 导航软件原型，输出动作建议和仿真路径，尚未连接真实机器人底盘。
